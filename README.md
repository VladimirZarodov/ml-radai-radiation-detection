# ML-RADAI: matched-filter radiation detection in urban search

A practical study of **anomaly detection for gamma-ray radiation sources** in the
[RADAI urban-search simulation dataset](https://bdc.lbl.gov/wiki/public/radai-interactive-datasets/)
(`training_v4.3.h5`, ORNL/LBNL). The final deliverable is
[`Matched_Filter_Detection.ipynb`](Matched_Filter_Detection.ipynb): a Poisson
matched-filter detector (7-component learned background + per-source templates,
62 s rolling-max aggregation **"mx31"**) with an honest episode-onset FAR
calibration (leave-one-run-out background pool) and full run-cluster bootstrap CIs.

**Headline result** (943 test encounters, runs 25–124, B_loo calibration):

| target FAR | encounter recall (95% CI) |
|---|---|
| 1 /h  | **25.2 %** [22.6–27.9] |
| 3 /h  | **40.5 %** [37.5–44.2] |
| 10 /h | **70.0 %** [66.8–73.5] |

Above mx31's structural FAR ceiling (~13 episodes/h) an **mx31 + ML (MLP) hybrid**
extends the working range: 89.3 % @FAR 30, 96.0 % @FAR 50, 98.9 % @FAR 100
(bootstrap CIs, no selection optimism).

**Caveat / Limitations:** the hard source groups — **NORM** (K-40, Th-232, Ra-226)
and **U-family** (DU, LEU, NatU, RefinedU) — remain largely **undetected by this
method family** at low FAR (9.7 % / 8.3 % recall @FAR 1): their spectra are
shape-indistinguishable from the U/Th background components. This is documented
in §4.1 and §6 of the notebook; the waterfall-CNN probe (§4.6) shows the door is
not closed by physics, only by this model class.

## Getting the data

`training_v4.3.h5` (~26.6 GB) is **not** in this repo (too large; also `.gitignore`d).

1. Register at [bdc.lbl.gov](https://bdc.lbl.gov/register) (academic requests approved ~24 h).
2. Download the RADAI **training** dataset v4.3 from the
   [dataset wiki page](https://bdc.lbl.gov/wiki/public/radai-interactive-datasets/).
3. Save it in the repo root **exactly as** `training_v4.3.h5`, next to
   `Matched_Filter_Detection.ipynb`.

## Running

```
python -m venv .venv && .venv\Scripts\activate     # Python 3.11
pip install -r requirements.txt
python -m notebook Matched_Filter_Detection.ipynb   # interactive run; or headless:
python _scratch/run_exec.py                          # executes + dumps all cell outputs
```

The notebook is **self-contained**: every intermediate cache it uses
(`_scratch/*.pkl`) is rebuilt from the raw `.h5` when absent. A verified full cold
run (fresh kernel, empty cache dir, executed top-to-bottom with `jupyter nbconvert
--execute`) took **~40 minutes** and reproduces every published number bit-for-bit
(headline asserts 25.2 / 40.5 / 70.0 % pass; §3.5 hybrid and §4.6 CNN re-derivations
included). The one heavy exception is
§4.6: if `_scratch/t5_wf.pkl` is missing the notebook automatically launches
`python _scratch/t5_waterfall.py` (torch CPU, seeded, ~10–20 min of the 40) before
evaluating.
`_scratch/` also keeps the standalone scripts behind §5 negative results; their
`.out` files are the canonical records.

## Repository layout

- `Matched_Filter_Detection.ipynb` — **the final deliverable** (fully executed).
  Section 0 is a self-contained intro: the physical task, the verified `.h5` schema
  (group layout, dtypes, field meanings), a glossary, the two related papers and the
  method explained in plain language — no prior radiation/ML knowledge assumed.
- `figures/` — PNGs saved by the notebook cells (used in this README).
- `_scratch/` — the notebook generator (`build_nb.py`), the headless executor
  (`run_exec.py`), standalone verification scripts cited by §5 of the notebook,
  and their canonical `.out` logs. Regenerable caches (`*.pkl`, `*.log`) are gitignored.

Earlier exploratory notebooks (dataset EDA, window-level LogReg/XGBoost/CNN attempts,
adaptive-background ideas) are no longer kept in the repo: their reproduced findings
are in §1–§2 of the notebook, and the dataset-schema documentation they contained was
verified against the `.h5` and moved into §0.2.
- `requirements.txt` — pinned versions (several findings are version-sensitive).
